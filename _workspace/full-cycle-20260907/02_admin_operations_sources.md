# rootHR 관리자 평가 운영 가이드 분석 — 16~26

- 확인일: 2026-09-07
- 범위: 사용자가 지정한 관리자 운영 11개 페이지
- 방법: 공식 페이지의 `betterdocs-single-content` 본문을 직접 읽고 상태 전이, 차단 조건, 역할, 알림, 산출물 연결만 재서술했다.
- 권한 표기의 한계: 문서는 실행 주체를 대부분 `관리자`라고만 부르며 제품 역할명이나 세부 권한 코드는 제공하지 않는다.

## 16. 평가 진행 대시보드 확인하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%ED%8F%89%EA%B0%80-%EC%A7%84%ED%96%89-%EB%8C%80%EC%8B%9C%EB%B3%B4%EB%93%9C-%ED%99%95%EC%9D%B8%ED%95%98%EA%B8%B0/)

- `평가관리 > 평가시행관리 > Dashboard`의 운영 현황 projection이다. 대상자 수, 중복 대상자, 제외자, 퇴직자와 평가자 그룹별 배정 수를 보여준다.
- 목표·중간점검·자기평가·평가·조정·Feedback의 시작일과 종료일, 단계별 대상·완료·미진행 인원을 집계한다.
- 읽기 화면이며 상태 변경, 취소, 재개, 알림 발송을 직접 수행하지 않는다. 지연이나 배정 누락을 찾은 뒤 해당 단계 탭으로 이동해 조치하는 구조다.
- 산출물은 별도 업무 레코드가 아니라 대상자·담당자·일정·진행 상태의 집계다. 새로고침 시 원천 상태와 일치해야 하며 집계 지연 여부는 문서에 없다.

## 17. 피평가자 생성 및 관리하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%ED%94%BC%ED%8F%89%EA%B0%80%EC%9E%90-%EC%83%9D%EC%84%B1-%EB%B0%8F-%EA%B4%80%EB%A6%AC%ED%95%98%EA%B8%B0/)

- 평가기준일의 인사·조직 정보와 등록 단계의 그룹 조건으로 대상자를 생성한다. 기존 생성자는 건너뛰므로 반복 실행은 중복을 만들지 않는 계약이다. 개별 추가와 엑셀 대량 업로드도 지원한다.
- 사번·성명·조직·직위 계열, 부서성과그룹, 피평가자그룹, 평가 기간, 가중치, 제외 여부를 확정한다. 부서 이동자는 복수 대상 행을 만들 수 있으나 한 직원의 가중치 합은 100이어야 한다.
- 그룹 변경 뒤 공통 문항 갱신을 별도로 실행해야 한다. 이를 빠뜨리면 새 그룹과 문항이 어긋난다.
- 일반 제외와 진행 내용까지 지우는 강제 삭제를 구분한다. 강제 삭제는 복구 불가라고 명시되어 감사·추가 확인이 필요한 파괴 작업이다.
- 선택 대상자에게 편집 가능한 메일을 보내며 회사명·직원명 토큰을 치환한다. 확정된 roster는 이후 합의자·점검자·평가자 생성의 입력이다.

## 18. 목표 단계 운영하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%EB%AA%A9%ED%91%9C-%EB%8B%A8%EA%B3%84-%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0/)

- 모든 피평가자에게 목표 합의자가 있어야 한다. 기본 합의자는 1차 상위 조직장이며 관리자가 다른 직원으로 바꿀 수 있다. 비매칭 대상이 남으면 시작 준비가 끝나지 않은 것이다.
- 합의자 생성 뒤 관리자가 전체·선택·개별 방식으로 상태를 `목표작성`으로 바꿔야 구성원 카드가 열린다.
- 구성원 흐름은 목표 작성 → 합의 요청 → 합의자의 승인 또는 반려다. 승인은 다음 단계의 완료 선행조건이고 반려는 목표 수정으로 되돌리는 업무 분기다.
- 선택 합의자에게 작성 안내 메일을 보낼 수 있다. 합의자 생성과 상태 변경은 독립 동작이므로 둘 중 하나만 수행하면 사용자가 진행할 수 없다.
- 취소·완료 재개 규칙은 이 페이지에 없다. “중간점검 미사용 시 해당 탭 미노출” 문구는 목표 페이지에 잘못 들어간 것으로 보이며 목표 단계 자체의 옵션 여부로 해석하면 안 된다.

## 19. 중간점검 단계 운영하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%EC%A4%91%EA%B0%84%EC%A0%90%EA%B2%80-%EB%8B%A8%EA%B3%84-%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0/)

- 평가 설정에서 중간점검을 사용한 경우에만 탭이 보인다. 모든 대상자에게 점검자를 생성하고 비매칭이 없는지 확인해야 한다.
- 준비 후 전체·선택·개별 상태 변경으로 `중간점검진행`에 진입시킨다. 이 상태가 되어야 점검자가 내용을 작성할 수 있고, 제출하면 `중간점검완료`가 다음 평가 단계의 선행조건이 된다.
- 선택 점검자에게 안내 메일을 보낼 수 있다. 문서는 점검자 기본 배정 규칙, 완료 취소·재개, 수정 잠금, 미완료자에 대한 강제 종료를 설명하지 않는다.
- 산출물은 대상자별 점검 담당자, 점검 내용, 완료 상태다. 단계를 사용하지 않는 평가에서는 이 노드를 건너뛰되, 구성된 단계를 임의로 건너뛰는 예외와 구분해야 한다.

## 20. 평가 단계 운영하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%ED%8F%89%EA%B0%80-%EB%8B%A8%EA%B3%84-%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0/)

- 성과·역량 평가는 조직장 계층과 사전 평가자 그룹으로 자기·1차·2차·3차 평가자와 차수별 가중치를 만든다. 다면평가는 관리자가 직접 구성하거나 부서장·본인의 제출안을 관리자가 최종 적용한다. 대상자별 가중치 합은 100이어야 한다.
- 평가자 생성 후 상태를 `평가요청`으로 바꾸고 첫 차수를 지정해야 카드가 열린다. 일괄 전이는 목표합의와, 설정된 경우 중간점검 완료 대상만 처리한다.
- 자기평가 사용 여부와 설정 차수에 따라 순차 진행하며 이전 차수 완료 시 다음 차수가 자동 활성화된다. 관리자는 현재 상태와 진행 차수를 확인한다.
- 평가자 교체, 엑셀 대량 매칭, 선택 평가자 메일 알림을 지원한다.
- 완료 취소는 가능할 수 있으나 평가 유형, 다른 평가자의 진행, 후속 단계 진입에 따라 달라진다고만 한다. 이 페이지에는 정확한 역전이 표가 없으므로 임의 상태 수정 API의 근거로 삼을 수 없다.

## 21. 평가 결과 계산하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%ED%8F%89%EA%B0%80-%EA%B2%B0%EA%B3%BC-%EA%B3%84%EC%82%B0%ED%95%98%EA%B8%B0/)

- 모든 평가 차수가 끝난 뒤 관리자가 계산을 실행한다. 차수 가중치, 척도·등급, 계산 방식, 상대평가 인원배분과 설정된 조정계수를 적용해 대상자별 계산점수·최종 점수·등급을 만든다.
- 계산 결과는 결과 조회, 조정, 통계, 공개의 공통 입력이다. 평가자별 원점수와 조정계수 계산 근거를 확인할 수 있어야 한다.
- 재계산은 가능하지만 기준 설정이 바뀐 경우에만 권장한다. 기존 계산 결과를 덮는지 버전을 남기는지는 설명하지 않는다.
- 다면평가의 일부 차수가 미완료이면 결과가 정상적이지 않을 수 있다고 경고한다. 서버가 계산을 거부한다고 명시하지는 않으므로, 구현 시 `미완료 차단`과 `경고 후 계산` 중 어느 정책인지 별도 결정이 필요하다.
- 계산 자체는 최종 확정이 아니다. 이후 조정 또는 마감·공개로 이어지며 알림 동작은 없다.

## 22. 조정 단계 운영하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%EC%A1%B0%EC%A0%95-%EB%8B%A8%EA%B3%84-%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0/)

- 조정을 사용하도록 구성한 평가만 대상이며 결과 계산 후에 시작한다. 조직 권한을 가진 최고 관리자를 조정자로 자동 배정하고 관리자가 교체할 수 있다. 기존 평가자로 참여한 대상은 자동 생성에서 제외된다는 문구가 있으나 정확한 이해충돌 규칙은 불명확하다.
- 조정자 배정 뒤 대상자를 `조정요청`으로 일괄·선택·개별 전환한다. 조정자는 점수·등급, 상대분포, 부서·그룹 편차를 보고 값 자체를 바꾸며 변경은 즉시 후속 공개·통계에 반영된다.
- 조정 완료가 다음 단계의 선행조건이지만 완료 상태명과 재개·취소 규칙은 없다.
- 페이지의 “중간점검자가 내용을 작성” 문장은 단계가 맞지 않는 복사 오류다. 구현 계약은 조정자 권한으로 해석해야 한다.
- 별도 메일 알림은 설명하지 않는다. 산출물에는 계산 원본과 조정값·사유·행위자를 분리해 감사할 필요가 있다.

## 23. 피드백 단계 운영하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%ED%94%BC%EB%93%9C%EB%B0%B1-%EB%8B%A8%EA%B3%84-%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0/)

- 확정된 평가 결과에 대해 담당자를 만들고 `feedback작성` 상태로 전환해야 작성 화면이 열린다. 담당자는 기본적으로 1차 상위 부서장이며 비매칭을 확인한다.
- 담당자는 점수·등급을 보며 코멘트를 저장하고 대상자에게 전달한다. 대상자는 합의하면 절차를 끝내고, 이의를 제기하면 상태가 `feedback 이의신청`으로 바뀐다.
- 이의신청 시 관리자 또는 담당자가 내용을 검토하고, 필요하면 점수·등급을 조정한 뒤 완료한다. 이 수정은 계산/조정 결과의 후속 변경이므로 이력과 사유 보존이 필요하다.
- 피드백을 사용하지 않는 회사는 마감 페이지 기준으로 이 단계를 생략할 수 있다. 이 페이지의 “조정 단계 미사용 시 탭 미노출” 문구는 피드백 설정을 가리키는 복사 오류 가능성이 높다.
- 완료 취소, 이의 철회, 재이의, 기한, 메일 알림은 설명하지 않는다.

## 24. 평가 마감 처리하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%ED%8F%89%EA%B0%80-%EB%A7%88%EA%B0%90-%EC%B2%98%EB%A6%AC%ED%95%98%EA%B8%B0/)

- 관리자는 점수·등급과 조정·피드백 누락을 확인한 뒤 마감한다. 피드백을 쓰지 않는 운영은 계산된 결과를 바로 마감할 수 있다. 마감 시 상태는 `최종완료`가 되고 결과는 잠긴다.
- 마감과 공개는 별개다. 결과집계에서 대상자별 오픈 여부를 저장해야 구성원의 결과 화면에 보이며, 미오픈 결과는 내부용으로 남는다. 공개 결과는 통계, 등급 매트릭스, 피드백 조회에도 반영된다.
- 문서에는 모순이 있다. 유의사항은 마감 후 수정·차수 되돌리기·평가 취소가 불가능하다고 하지만, 별도 `마감 취소` 절차는 결과집계의 대상 행을 삭제하고 상태 변경·재계산 후 순서대로 다시 처리하라고 한다.
- 따라서 직접적인 `최종완료 → 진행중` 역전이보다, 권한 있는 집계 삭제/재개 보상 명령으로 해석하는 편이 안전하다. 삭제 범위, 공개 회수, 재오픈 알림, 감사 규칙은 추가 확인이 필요하다.

## 25. (성과/역량) 평가 상태 변경하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%EB%8B%A8%EC%9D%BC%ED%8F%89%EA%B0%80-%EC%83%81%ED%83%9C-%EB%B3%80%EA%B2%BD%ED%95%98%EA%B8%B0/)

- 전체 흐름은 `목표작성 → 중간점검진행 → 평가요청(자기·1차·2차) → 조정요청 → 피드백작성` 순서다. 구성하지 않은 선택 단계는 빠질 수 있지만, 구성된 중간 단계는 건너뛸 수 없다.
- 일괄 변경은 이전 단계 완료자만 처리하고 미완료자는 제외한다. 평가요청의 첫 차수를 지정하면 이후 차수는 제출 완료에 따라 자동 전진한다.
- 개별 행이나 선택 목록은 상태와 차수를 직접 바꿔 즉시 반영한다. 문서는 완료한 평가를 다시 진행시키는 예외 처리에도 쓴다고 하지만 허용 가능한 역전이와 후속 데이터 보존 규칙은 주지 않는다.
- 변경 후 직원평가보기에서 해당 평가자에게 카드가 실제 노출되는지 확인한다. 카드가 없으면 상태 또는 차수 누락을 의심한다.
- 관리자 전용 운영 기능이며 알림은 없다. 구현은 일괄 결과에 변경·미완료 제외·오류 사유를 각각 반환해야 한다.

## 26. 직원 평가 화면 확인하기

[원문](https://roothr.co.kr/guide/admin-guide/evaulation/%EC%A7%81%EC%9B%90-%ED%8F%89%EA%B0%80-%ED%99%94%EB%A9%B4-%ED%99%95%EC%9D%B8%ED%95%98%EA%B8%B0/)

- 관리자가 직원을 검색해 그 직원이 보는 화면과 진행 위치를 점검하는 문의 대응용 읽기 기능이다. 세션을 직원으로 바꾸는 동작이 아니라 관리자 관점의 동일 projection으로 해석해야 한다.
- `나의 평가`는 진행 평가명과 목표·자기평가·Feedback 완료 여부를 카드로 보여준다. `구성원 평가`는 목표·중간점검·평가·조정·Feedback별 대상·요청·종료 수를 보여주고, 다면평가 참여 시 차수별 대상·요청·완료 수도 제공한다.
- `개인 평가결과`는 마감되고 결과집계에서 공개된 경우에만 열리며 최근 5년 추이·분포와 연도·유형·점수·등급을 표시한다.
- 상태 변경이나 알림은 수행하지 않는다. 민감한 타인 결과를 보므로 문서의 단순 `관리자`보다 좁은 조회 권한과 접근 감사가 필요하지만 구체 역할은 출처에 없다.

## 운영 상태와 산출물 연결

| 운영 노드 | 진입 조건 | 수행 주체/산출물 | 다음 단계 차단 |
|---|---|---|---|
| 대상자 확정 | 평가 설정 + 기준일 인사·조직 | 관리자 / roster·그룹·가중치·제외 여부 | 대상자 없이는 담당자 생성 불가 |
| 목표작성 | 합의자 배정 + 상태 전환 | 피평가자·합의자 / 목표·승인 또는 반려 | 합의 미완료자는 다음 일괄 전이 제외 |
| 중간점검진행 | 선택 단계 + 점검자 배정 | 점검자 / 점검 내용·완료 | 완료 전 평가요청 차단 |
| 평가요청 | 평가자·차수·가중치 확정 | 자기/1~3차 평가자 / 차수별 제출 | 이전 차수 완료 전 다음 차수 비활성 |
| 결과계산 | 평가 차수 완료 | 관리자 / 계산점수·점수·등급·근거 | 미완료 시 명시적 hard fail 여부 불명 |
| 조정요청 | 선택 단계 + 계산 결과 + 조정자 | 조정자 / 조정 점수·등급 | 조정 완료 전 후속 확정·공개 차단 |
| feedback작성 | 선택 단계 + 담당자 + 확정 결과 | 담당자·피평가자 / 코멘트·합의/이의 | 이의 미처리 시 완료 불가 |
| 최종완료 | 최종 값과 누락 점검 | 관리자 / 잠긴 최종 결과 | 직접 수정·차수 역전 금지 |
| 결과 공개 | 최종완료 + 대상별 open | 관리자 / 구성원 결과·통계 projection | 미오픈이면 내부 조회만 |

## 구현 전에 고정해야 할 불확실성

1. 선택 단계가 없는 평가에서 허용할 정확한 축약 상태 그래프
2. 차수별 완료 취소의 허용 조건, 이미 시작한 다음 차수의 무효화 범위
3. 결과 계산 시 미완료자가 한 명이라도 있으면 전체 차단할지, 대상별 제외 계산할지
4. 재계산이 기존 결과를 덮는지, 계산 revision을 추가하는지
5. 조정값과 피드백 이의 처리값의 우선순위 및 원점수 보존 방식
6. 마감 취소 시 삭제되는 `결과집계`의 정확한 범위와 이미 공개된 결과의 회수 방식
7. 개별 상태 수정이 순서 가드를 우회할 수 있는지와 모든 예외 변경의 감사 사유 필수 여부
8. 단계 시작·리마인드·반려·이의·재오픈 중 어떤 사건이 자동 알림이고 어떤 사건이 수동 메일인지

## 출처에서 확인된 문서 결함

- 목표 운영 페이지의 중간점검 탭 노출 문구는 문맥상 위치가 잘못됐다.
- 조정 운영 페이지가 조정 시작의 효과를 중간점검자 작성 허용으로 설명한다. 조정자 작성 허용의 복사 오류로 보인다.
- 피드백 운영 페이지가 조정 단계 미사용 여부로 피드백 탭 노출을 설명한다. 피드백 단계 설정과의 관계를 관리자 설정 페이지에서 재검증해야 한다.
- 마감 페이지는 마감 후 취소 불가와 마감 취소 절차를 동시에 제시한다. 구현은 이를 단일 무제한 역전이로 단순화하면 안 된다.
