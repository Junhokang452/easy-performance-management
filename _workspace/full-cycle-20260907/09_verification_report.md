# 관리자·구성원 평가 전체 사이클 구현 및 검증

관리자 32개, 구성원 16개 RootHR 가이드의 업무를 성과관리 제품으로 구성했다. 설정 → 목표 합의 → 중간점검 → 자기평가 → 1~3차 평가 → 계산·조정 → 피드백·이의 → 마감·개별 공개가 하나의 프로그램·참여자·결과 이력으로 연결된다.

## 구현 범위

| 영역 | 화면과 동작 |
|---|---|
| 관리자 설정 | 성과·역량 항목, 부서 목표, 프로그램 기본 정보·복사, 단계, 입력·결과 척도, 조건별 그룹, 공통항목, 부서 성과 그룹, 인원 배분, 공개 정책 |
| 운영 | 대상자·발령별 참여 가중치, 평가자 배정, Excel 가져오기/내보내기, 안내 첨부, 단계별 대시보드, 완료자 진행·미완료자 제외, 개별 예외 변경, 알림 미리보기·대기·발송 |
| 구성원 | 목표 작성·수정·합의 요청·반려 후 재요청·이력, 자기신고, 중간점검 근거 조회, 자기평가 저장·제출, 결과 동의·이의, 공개된 개인 이력·알림함 |
| 평가자 | 배정된 직원 업무함, 목표 합의, 중간점검 저장·완료, 차수별 평가, 조정 초안·완료, 최종 피드백·이의 처리 |
| 과제·면담 | 체크리스트/실적 과제, 상태·재개·관계자·라벨·활동·첨부·별점; 면담 네 가지 보기와 구조화된 내용, 대상자/참조자별 공개·철회 |
| 결과·분석 | 항목별·평가자별·직원별 결과, 두 평가 등급 매트릭스·대상자 상세, 등급 축을 포함한 맞춤통계, 실제 XLSX/SVG 다운로드, 평가자 평균·표준편차·의견 길이·키워드와 분석 방법 안내 |

일반 성과·역량 평가는 이 제품이 담당한다. 다면진단의 캠페인·응답·익명 집계·보고서는 easy-mra, 학습·IDP는 easy-learning-management의 영역으로 유지한다. 설정에 남아 있는 기존 다면평가 코드값은 신규 생성에서 거부한다.

## 설계와 재사용

- 고객별 Neon 프로젝트 아래 자매품별 DB를 두는 Model B를 유지한다. 성과 데이터는 고객사의 `performance` DB, 애플리케이션 역할은 `performance_app`이다. 로그인 테넌트 UUID를 제품군에서 공유한다.
- 인증·테넌트 라우팅·감사·표준 오류·UUID 등은 easy-platform-core를 사용한다. 평가 정책·산식·상태 전이는 제품에 둔다.
- Easy Design System의 SuiteShell·공통 폼·조회 선택기·표·표시 컴포넌트를 사용한다. WorkflowPhaseRail과 MasterDetailWorkspace는 공통 자산으로 등록했으며, 실제 XLSX 처리는 공유 SimpleXlsx를 사용한다.
- 한국어·영어·일본어·중국어 간체·베트남어를 지원한다. 신규 화면은 페이지별로 지연 로딩한다.

## 실행 범위

[로컬 화면](http://localhost:5174)과 저장소 README의 역할별 데모 계정으로 확인할 수 있다. 현재 서버는 합성 데이터 전용이다. 운영 Neon/control plane 변경, 외부 메일 발송, Git push와 클라우드 배포는 실행하지 않았다. SMTP 미설정 상태를 발송 완료로 표시하지 않으며, 실제 전송 어댑터는 로컬 SMTP 검증을 통과했다. Docker 엔진을 이용한 최종 이미지 빌드는 이번 검증에 포함하지 않았다.
