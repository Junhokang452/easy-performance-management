# RootHR 관리자 평가 설정 가이드 분석 (담당 1·3·4·5·6·7·11·12·13·14)

- 조사일: 2026-09-07
- 범위: 공개 RootHR 관리자/활용 가이드 중 평가 준비와 등록에 해당하는 10개 문서
- 판독 원칙: 아래의 `잠금`은 문서가 명시한 내용만 적었다. 화면에 보이지 않는 검증식·수정 가능 상태·조건식의 AND/OR 의미는 `불확실`로 분리했다.

## 1. 인사평가 관리 개요

- **출처:** [인사평가 관리 개요](https://roothr.co.kr/guide/use-cases/evaulation/%EC%9D%B8%EC%82%AC%ED%8F%89%EA%B0%80-%EA%B4%80%EB%A6%AC-%EA%B0%9C%EC%9A%94/) (2026-01-09 갱신)
- **필드/구조:** 단일 필드 화면보다 전체 메뉴 지도를 설명한다. 사전 기준은 성과항목·역량항목·부서별 성과항목·부서목표, 평가 등록 기준은 단계·결과계산·척도·인원배분·결과공개·피평가자그룹·공통항목·부서성과그룹이다.
- **규칙:** 기준 정의 → 평가 등록 → 대상/평가자 생성 → 목표·중간점검·평가 → 계산·조정 → 피드백·마감 → 결과/통계 순서다.
- **행동:** 등록, 운영현황/대시보드 확인, 진행 요청, 결과 조회, 등급·부서목표 통계 분석.
- **잠금:** 명시된 잠금 없음. 다만 사전 기준과 평가별 기준이 구분된다.
- **불확실:** 단계별 수정 가능 시점, 재개방, 삭제·복사 범위는 하위 가이드 확인이 필요하다.

## 3. 성과평가 항목 설정하기

- **출처:** [성과평가 항목 설정하기](https://roothr.co.kr/guide/use-cases/evaulation/%EC%84%B1%EA%B3%BC%ED%8F%89%EA%B0%80-%ED%95%AD%EB%AA%A9-%EC%84%A4%EC%A0%95%ED%95%98%EA%B8%B0/) (2026-01-09 갱신)
- **필드:** 직무항목 검색은 대·중·소분류, 직접 입력은 대·중·소분류·평가항목·정의, 대량 입력은 내려받은 엑셀 양식을 사용한다.
- **규칙:** 평가 생성 전에 만드는 공통 카탈로그다. 부서별 항목, 평가별 공통항목, 구성원 목표의 선택 원천이 된다.
- **행동:** 직무평가항목 검색/선택/추가, 텍스트 추가, 엑셀 다운로드·업로드, 저장.
- **잠금:** 카탈로그 수정이 이미 생성된 평가 구성에 자동 반영되지 않을 수 있다. 이는 평가가 원천 항목의 스냅샷 또는 명시적 반영본을 가져야 함을 뜻한다.
- **불확실:** 항목 코드, 활성/폐기 상태, 중복 판정, 분류 자체 편집, 기존 평가로의 수동 재반영 절차는 설명되지 않는다.

## 4. 역량평가 항목 설정하기

- **출처:** [역량평가 항목 설정하기](https://roothr.co.kr/guide/use-cases/evaulation/%EC%97%AD%EB%9F%89%ED%8F%89%EA%B0%80-%ED%95%AD%EB%AA%A9-%EC%84%A4%EC%A0%95%ED%95%98%EA%B8%B0/) (2026-01-09 갱신)
- **필드:** 사전 선택 항목 또는 직접 입력한 역량유형·역량명·역량정의. 대량 입력은 엑셀 양식을 사용한다.
- **규칙:** 태도·문제해결·협업처럼 수치만으로 보이지 않는 요소의 기준 카탈로그다. 공통평가항목, 피평가자그룹별 지정 항목, 성과·역량 평가에 쓰인다.
- **행동:** 역량사전 검색/선택, 텍스트 추가, 엑셀 다운로드·업로드, 저장.
- **잠금:** 평가 생성 전 준비를 권장하지만 생성 후 수정 전파나 명시적 잠금 규칙은 기술하지 않는다.
- **불확실:** 역량 수준(level)·행동지표·직급별 기대수준, 항목 중복/폐기, 평가별 스냅샷 방식은 설명되지 않는다.

## 5. 부서별 성과평가 항목 구성하기

- **출처:** [부서별 성과평가 항목 구성하기](https://roothr.co.kr/guide/use-cases/evaulation/%EB%B6%80%EC%84%9C%EB%B3%84-%EC%84%B1%EA%B3%BC%ED%8F%89%EA%B0%80-%ED%95%AD%EB%AA%A9-%EA%B5%AC%EC%84%B1%ED%95%98%EA%B8%B0/) (2026-01-09 갱신)
- **필드:** 조직 기준일, 조직도의 부서, 성과평가 항목 참조.
- **규칙:** 사전 등록된 성과항목만 선택할 수 있다. 모든 부서에 필수는 아니며 업무 특성이 다른 부서에 선택 적용한다. 이후 평가별 부서 항목, 피평가자그룹 항목, 개인 목표의 참고 원천이 된다.
- **행동:** 기준일 입력, 부서 선택, 항목 검색/선택/추가, 삭제, 저장.
- **잠금:** 문서상 잠금 없음. `기준일`은 당시 조직 구조를 선택하기 위한 유효시점이다.
- **불확실:** 상위 부서 항목 상속, 겸직자 처리, 기준일 이후 조직 이동, 삭제가 이미 만든 평가/목표에 미치는 영향은 설명되지 않는다.

## 6. 부서 목표 등록하고 관리하기

- **출처:** [부서 목표 등록하고 관리하기](https://roothr.co.kr/guide/use-cases/evaulation/%EB%B6%80%EC%84%9C-%EB%AA%A9%ED%91%9C-%EB%93%B1%EB%A1%9D%ED%95%98%EA%B3%A0-%EA%B4%80%EB%A6%AC%ED%95%98%EA%B8%B0/) (2026-01-14 갱신)
- **필드:** 회사 또는 부서, 시작일, 종료일, 목표 문장.
- **규칙:** 평가 점수를 직접 만드는 항목이 아니라 평가기간의 방향과 맥락을 제공하는 선택 정보다. 성과항목과 1:1 대응할 필요가 없고 구성원이 개인 목표를 작성할 때 참고한다.
- **행동:** 조직도에서 회사/부서 선택, 추가, 기간·목표 입력, 저장.
- **잠금:** 문서상 잠금 없음.
- **불확실:** 목표 계층/정렬, 여러 목표의 우선순위, 달성률, 승인, 조직 변경 시 승계, 평가 사이클과의 직접 연결 방식은 설명되지 않는다.

## 7. 평가 등록하고 기본 정보 설정하기

- **출처:** [평가 등록하고 기본 정보 설정하기](https://roothr.co.kr/guide/use-cases/evaulation/%ED%8F%89%EA%B0%80-%EB%93%B1%EB%A1%9D%ED%95%98%EA%B3%A0-%EA%B8%B0%EB%B3%B8-%EC%A0%95%EB%B3%B4-%EC%84%A4%EC%A0%95%ED%95%98%EA%B8%B0/) (2026-01-12 갱신)
- **필드:** 평가유형(성과·역량·다면·종합), 평가명, 평가년도, 기준일, 평가시작일, 평가종료일, OPEN 여부.
- **규칙:** 등록은 점수 입력이 아니라 평가 틀/기간 생성이다. OPEN이면 기준 설정과 후속 단계 운영이 가능하고, 미OPEN이면 기본 정보만 저장된다. 기존 평가 복사는 같은 평가유형이며 새 평가 시작일보다 앞선 평가만 가능하다.
- **행동:** 추가/저장, OPEN 전환, 조건을 만족하는 이전 평가 기준 복사.
- **잠금:** OPEN 이후 어떤 필드가 잠기는지는 명시하지 않는다. 후속 대상/평가자 생성 전에 단계·계산·척도·피평가자그룹 설정을 완료해야 한다.
- **불확실:** 유형 복합 선택, 기준일의 조직 스냅샷 의미, OPEN 취소, 평가 기준 복사 범위·참조/복제 방식은 설명되지 않는다.

## 11. 피평가자 그룹 구성하기

- **출처:** [피평가자 그룹 구성하기](https://roothr.co.kr/guide/use-cases/evaulation/%ED%94%BC%ED%8F%89%EA%B0%80%EC%9E%90-%EA%B7%B8%EB%A3%B9-%EA%B5%AC%EC%84%B1%ED%95%98%EA%B8%B0/) (2026-01-14 갱신)
- **필드:** 그룹명·정의, 항목방식(합의/지정), 평가방식(상대/절대), 중간점검·자기평가 ON/OFF, 평가자 수별 가중치(1명/2명/3명 이상), 부서성과 가중치, 우선순위, 조건의 항목·연산자·코드(부서/직책 포함·제외 등).
- **규칙:** 실제 평가자 수 케이스마다 평가자 및 부서성과 가중치 합이 100%여야 한다. 2·3차 평가를 쓰더라도 예외 대상용 하위 평가자 수 표가 필요하다. 조건이 겹치면 가장 높은 우선순위 그룹 하나가 적용된다. 상대평가는 인원배분과 결합한다.
- **행동:** 그룹 추가, 속성/가중치 저장, 끌어놓기로 우선순위 변경, 조건 추가·코드선택·저장.
- **잠금:** 명시된 잠금 없음.
- **불확실:** 조건 간 AND/OR, 3명 초과 개별 차수, 대상 생성 후 그룹 변경/재매칭, 합의·지정의 상세 상태기계는 후속 문서가 필요하다.

## 12. 공통평가항목 구성하기

- **출처:** [공통평가항목 구성하기](https://roothr.co.kr/guide/use-cases/evaulation/%EA%B3%B5%ED%86%B5%ED%8F%89%EA%B0%80%ED%95%AD%EB%AA%A9-%EA%B5%AC%EC%84%B1%ED%95%98%EA%B8%B0/) (2026-01-14 갱신)
- **필드:** 기존 항목 선택 시 피평가자그룹·가중치·순서·등급/점수 기준. 직접 입력 시 평가항목·정의가 추가된다. 다면평가는 평가차수와 코드/텍스트 항목 방식도 지정한다.
- **규칙:** 척도와 피평가자그룹 설정 후 구성한다. 그룹×평가차수별 가중치 합은 100%여야 한다. 평가자 화면에 자동 노출되고 차수별 계산에 반영되며 다면평가 문항을 통일한다.
- **행동:** 기존 항목 일괄선택 또는 텍스트 추가, 코드 등록/선택, 저장, `공통평가항목재반영` 실행.
- **잠금:** 저장만으로 기존 평가에 반영되지 않고 명시적 재반영이 필요하다. 재반영 이후 잠금 시점은 설명되지 않는다.
- **불확실:** 재반영이 기존 응답을 보존/초기화하는지, 부분 재반영·버전 이력·차수별 가중치 오차 허용치는 설명되지 않는다.

## 13. 부서성과그룹 구성하기

- **출처:** [부서성과그룹 구성하기](https://roothr.co.kr/guide/use-cases/evaulation/%EB%B6%80%EC%84%9C%EC%84%B1%EA%B3%BC%EA%B7%B8%EB%A3%B9-%EA%B5%AC%EC%84%B1%ED%95%98%EA%B8%B0/) (2026-01-14 갱신)
- **필드:** 부서성과그룹명, 등급, 순서, 조건의 항목·연산자·코드.
- **규칙:** 평가결과 계산에서 부서성과그룹 적용을 선택했을 때만 구성한다. 같은 방식/기준으로 평가받는 부서 묶음이다. 조직도 기준 자동생성 시 현재 부서 목록과 각 부서를 포함하는 기본 조건이 생성된다.
- **행동:** 그룹 추가 또는 조직도 기준 생성, 이름·등급·순서 입력/저장, 조건 추가, 항목·연산자·코드 선택, 저장.
- **잠금:** 문서상 잠금 없음.
- **불확실:** 조건 중첩 우선순위, 등급의 척도 참조, 그룹 점수 산식, 조직 개편 시점, 미매칭 부서 처리, 그룹 등급이 개인 결과에 반영되는 방식은 설명되지 않는다.

## 14. 인원배분 설정하기

- **출처:** [인원배분 설정하기](https://roothr.co.kr/guide/use-cases/evaulation/%EC%9D%B8%EC%9B%90%EB%B0%B0%EB%B6%84-%EC%84%A4%EC%A0%95%ED%95%98%EA%B8%B0/) (2026-01-14 갱신)
- **필드:** 최대 피평가자 수, 평가 인원(모집단 크기)별 성과등급, S/A/B/C/D 등급별 인원 수.
- **규칙:** 상대평가 시 필수다. 최대 인원을 기준으로 모집단 크기별 행을 자동 생성하며, 각 행의 등급별 인원 합은 해당 평가 인원 수와 정확히 일치해야 한다. 부서성과그룹·피평가자그룹·상대평가 기준 단위와 함께 결과 계산에 적용된다.
- **행동:** 최대 인원 입력, `인원배분생성`, 각 행의 등급별 수 입력, 저장. 작은 1~5명 구간부터 확장을 권장한다.
- **잠금:** 문서상 잠금 없음.
- **불확실:** 동점 처리, 미설정 모집단 크기, 인원 증감 시 재계산, 0명 등급 허용, 등급 종류 변경 시 행 이관, 반올림은 설명되지 않는다.

### 구현에 필요한 추가 aggregate

1. **평가 등록 revision:** `EvaluationDefinitionRevision`에 평가유형, 평가년도, 기준일, OPEN, 선택 단계와 설정 스냅샷을 둔다. OPEN 이후에는 새 revision으로만 변경한다.
2. **항목 카탈로그:** `EvaluationItem`(PERFORMANCE/COMPETENCY), 분류·정의·코드·활성 상태와 `DepartmentItemAssignment(effectiveDate, orgUnitId, itemId)`를 둔다. 평가별 `EvaluationItemSnapshot`으로 원천 수정과 실행 데이터를 분리한다.
3. **조직 목표:** `DepartmentGoal(orgUnitId, startDate, endDate, text)`를 두되 점수 항목과 분리한다. 필요 시 KPI cascade의 참고 링크만 허용한다.
4. **피평가자 규칙:** `RevieweeGroup` + 순서 있는 `RevieweeGroupCondition` + `ReviewerCountWeightPlan`을 둔다. 그룹 매칭 결과는 대상 생성 시 `Participant.groupId`와 조건/조직 기준일 snapshot으로 동결한다.
5. **공통 항목:** `GroupRoundItem(groupId, round, itemSnapshotId, scaleId, weight, order)`와 명시적 `applyRevision`을 둔다. 그룹×차수 합계 100%를 DB/서비스 경계에서 검증한다.
6. **부서성과/배분:** `DepartmentPerformanceGroup`·조건·등급과 `HeadcountAllocationPlan(populationSize, grade, headcount)`을 둔다. 각 모집단 행 합계 일치와 지원 범위를 검증하고 계산/조정에는 적용 revision ID를 기록한다.

### 현재와의 핵심 간극

- 현재 roster 입력은 `employeeId + managerEmployeeId`이며 `ParticipantRosterService`가 **MANAGER 1차, 가중치 100%**만 생성한다. 그룹 조건 매칭, 2·3차/다면 평가자, 평가자 수별 대체 가중치가 없다.
- `EvaluationPolicy.forcedDistribution`은 **등급 비율 JSON**이고 현재 배분은 전사 기준이다. RootHR의 모집단 크기별 **정수 headcount 표** 및 피평가자/부서성과 그룹별 계산 단위와 다른 개념이다.
- `KpiNode`는 실행 목표로 재사용할 수 있지만 성과/역량 카탈로그, 행동 문항, 그룹×차수 공통항목의 원천·스냅샷을 대신하지 못한다.
- 현재 cycle은 기간/유형만 가지며 평가년도·조직 기준일·OPEN·평가 구성 복사/revision이 없다. `PLANNED/ACTIVE`를 OPEN과 억지로 동일시하지 말고, 설정 게시 상태와 실행 단계를 분리하는 편이 안전하다.
