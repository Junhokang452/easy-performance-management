# 구성원 평가 가이드 — 핵심 단계 요구사항

분석일 2026-09-07. 아래 내용은 원문 인용이 아닌 구현 요구 요약이다. 사용자 제공 링크 17개 중 평가 결과 조정 링크가 중복되어 고유 문서는 16개다. 평가자 피드백 작성 문서 1개는 단계 연결 확인을 위해 추가 참고했다.

## M01 나의 평가 수행하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/나의-평가-수행하기/)

본인에게 배정된 평가를 카드로 조회하고, 설정된 단계만 수행한다. 기본 축은 목표→자기평가→피드백이며 유형에 따라 단계 생략이 가능하다. 목표는 합의형/자기신고형 두 경로다. 목표·성과과제·활동·면담 자료가 자기평가의 근거가 된다. 구현에서는 회사 전체 진행 상태와 개인의 단계 상태를 분리하고, 현재 할 일·기간·대기 사유·완료 상태를 표시한다(상태 모델은 설계 제안).

## M02 목표 수립하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/목표-수립하기/)

제목, 항목정의, 가중치, 등급/점수 기준, 등급별 달성수준을 입력한다. 여러 목표의 가중치 합은 100%다. 목표 추가·수정 외에 작성 의견 저장, 합의 요청, 반려 의견 확인, 재작성·재요청 경로가 필요하다. 자기신고형은 합의 없이 확정한다. 설정에 따라 부서목표 선택/연결 표시, 직무·공통 평가항목 검색/선택/자동 채움이 제공된다. 목표 수준 정의와 선택 항목은 해당 평가의 기준으로 보존해야 한다(스냅샷은 설계 제안). 본문은 웹 도구 시간 초과 후 동일 URL 직접 HTTP 200으로 확인했다.

## M03 자기평가하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/자기평가하기/)

목표별 부서연계·정의·달성수준을 참고하면서 등급 또는 점수를 입력한다. 항목별 의견의 필수 여부는 설정에 따르고, 별도의 종합 의견도 작성한다. 임시 저장과 최종 완료를 구분하며, 제출 후 수정 제한을 적용한다. 단일 종합 점수 입력으로 대체하지 않는다.

## M04 피드백 확인하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/피드백-확인하기/)

본인 평가의 최종 결과·피드백 확인 후 합의 또는 이의신청을 한다. 합의 시 의견은 선택, 이의는 구체적 사유를 받는다. 이의 이후 평가자 재검토/추가 조정이 가능하다. 개인의 합의 완료와 전사 사이클 마감은 구분해야 한다(설계 제안). 피드백 단계 자체의 제공 여부는 설정 의존이다.

## M05 구성원 평가 수행하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/구성원-평가-수행하기/)

여기서 구성원 평가는 '내가 다른 직원을 평가하는 업무'다. 합의자·평가자·조정자·최종 평가자의 역할에 따라 목표합의→중간점검→평가→조정→피드백 작성이 연결된다. 선택 단계와 권한을 평가 설정에서 결정한다. 일반 평가자는 조정 결과를 조회할 수 있으며, 피드백 기록은 종료 후에도 조회한다. 인사 운영 관리자와 평가자 권한을 같은 역할로 묶으면 안 된다(설계 제안).

## M06 목표 합의하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/목표-합의하기/)

합의 요청 직원 목록에서 대상을 선택하고 부서연계·정의·수준·가중치를 검토한다. 의견 임시 저장→합의 또는 반려가 가능해야 한다. 반려 시 구성원이 보완 후 재요청하며, 목표 수정/합의 이력을 확인한다. 합의가 필요한 평가에서 미합의 상태의 후속 진행을 막는다. 작성 의견을 합의/반려 동작과 독립적으로 저장해야 한다.

## M07 중간점검 진행하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/중간점검-진행하기/)

설정된 경우 평가자가 대상 직원을 선택해 과제 목록·진행률·진행 그래프·상세 활동을 확인하고 점검 의견을 작성, 완료한다. 평가 점수를 매기는 단계가 아니다. 이 의견은 최종 평가 참고자료로 다시 나타나야 한다. 구성원의 지속적 실적 기록과 평가자의 중간점검 완료는 별개 상태로 관리한다(설계 제안).

## M08 평가 작성하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/평가-작성하기/)

그룹·차수·요청/완료 인원 및 자기/1차/2차 등의 상태를 표로 조회한다. 대상자 상세에서 목표·합의 이력, 면담, 중간점검, 자기평가를 함께 참고한다. 항목별 등급/점수와 차수별 의견을 작성하고 저장/완료를 구분한다. 연계 성과과제의 진행률·활동·체크리스트는 판단 근거이며 자동 점수 산식으로 간주하지 않는다. 다차수 선후행·이전 차수 공개 범위는 관리자 가이드에서 확정할 사항이다.

## M09 평가 결과 조정하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/구성원-평가-결과-조정하기/)

지정된 조정자가 그룹/직원을 선택하고 기존 평가를 조회해 점수·등급을 수정한다. 초안 저장 중에는 수정할 수 있고 완료 후 잠긴다. 상대평가 그룹에는 등급별 기준 인원과 현재 인원을 함께 표시하며 등급 변경 때 즉시 갱신한다. 배분 충족 판정은 점수 자체가 아니라 등급 인원이다. 반올림·예외 허용 정책은 문서만으로 확정할 수 없다.

## M15 평가 피드백 확인하기

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/평가-피드백-확인하기/)

과거 평가를 연도·유형·평가명·점수/등급으로 선택하고, 항목 정의와 평가자 의견을 조회하는 별도 피드백 보관 화면이다. 다면평가가 있는 경우 자기·상사·동료·부하 비교 그래프를 제공한다. 합의/이의 처리 화면과 역할이 다르다. 다면 결과는 기존 easy-mra 연계 및 익명성 기준 확인이 필요하다(자매품 설계 제안).

## A01 추가 참고: 최종 평가자 피드백 작성

[출처](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/구성원-평가-결과에-피드백-남기기/)

최종 평가자가 대상자의 등급·점수를 참고해 종합 피드백을 쓰고 완료한다. 완료 후 수정할 수 없고 종료된 평가 단계에서 새 피드백을 작성할 수 없다. 평가 확정→피드백 완료→구성원 합의→사이클 마감의 각 완료 의미는 관리자 가이드와 결합해 명확히 정의해야 한다.

## 출처 확인의 한계

일부 외부 이미지 URL은 시간 초과/접근 제한으로 상세 화소를 확인하지 못했다. 문서에서 설명한 목록·팝업·표·그래프 구성은 확인했지만 모든 이미지의 작은 버튼이나 픽셀 단위 화면을 확인했다고 주장하지 않는다. 기능/과정은 본문을 기준으로 정리하며, 실제 UI는 easy-ware/easy-hcm 공유 디자인을 적용한다.
