# rootHR 구성원 보조 가이드 분석

- 확인일: 2026-09-07
- 범위: 요청받은 구성원 가이드 6개 페이지만 분석
- 목적: 문구 복제가 아니라 구현에 필요한 기능, 입력, 권한, 단계, 상태, 관리자 설정 의존성 추출
- 이미지 근거: 본문에 연결된 스크린샷 자산은 별도 `roothr.mycafe24.com` 호스트에 있으며 일부가 시간 초과됐다. 따라서 이미지의 세부 배치·색상·버튼 문구는 확정하지 않고, 본문이 명시한 카드·탭·그래프·오른쪽 상세 영역만 반영했다.

## 1. 부서 목표 조회하기

[원문](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/%EB%B6%80%EC%84%9C-%EB%AA%A9%ED%91%9C-%EC%A1%B0%ED%9A%8C%ED%95%98%EA%B8%B0/) · 업데이트 2025-12-18

- **기능/단계:** `평가 > 평가 수행 > 부서 목표현황`에서 왼쪽 조직도의 소속 부서를 선택하고 해당 부서 목표 목록을 본다. 개인 목표를 작성하기 전 조직 방향을 이해하는 참조 화면이다.
- **입력:** 부서 선택 외 작성 입력은 없다.
- **권한:** 구성원은 조회만 가능하며 목표 수정 권한이 없다.
- **관리자 의존:** 부서 관리자 또는 평가 관리자가 목표를 먼저 설정해야 한다. 조직도와 사용자의 소속 부서 정보도 준비되어야 화면이 의미를 갖는다.
- **불확실:** 상·하위 부서까지 탐색 가능한지, 목표의 기간·상태·가중치가 노출되는지, 비활성 목표를 숨기는지는 페이지에서 설명하지 않는다. 연결 이미지도 안정적으로 열리지 않아 목록 컬럼은 확인하지 못했다.

## 2. 성과과제 등록하고 관리하기

[원문](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/%EC%84%B1%EA%B3%BC%EA%B3%BC%EC%A0%9C-%EB%93%B1%EB%A1%9D%ED%95%98%EA%B3%A0-%EA%B4%80%EB%A6%AC%ED%95%98%EA%B8%B0/) · 업데이트 2025-12-19

- **기능/입력:** `평가 수행 > 성과과제 관리`에서 과제명, 기간, 단계, 설명, 달성 방식(Check List 또는 실적), 연결할 개인·부서 목표, 담당·관리·협업 관계자를 등록한다. 상세는 속성·활동·피드백 탭으로 나뉜다.
- **상태/진행:** 카드를 끌어 `계획 → 진행중 → 완료/폐기`로 옮길 수 있다. FAQ에서는 폐기를 `휴지통`이라고도 불러 용어 통일이 필요하다. 체크리스트 방식은 완료 항목으로 진행률을 자동 계산하고, 실적 방식은 진행률과 진척 내용을 직접 입력한다.
- **협업:** 활동 메시지와 파일을 남기고, 관계자에게 별점과 메시지 피드백을 보낸다. 라벨을 생성·적용하고 라벨로 목록을 거른다.
- **권한/관리자 의존:** 관계자로 지정된 사람만 활동과 피드백을 공유한다. 연결 가능한 합의된 목표가 먼저 존재해야 한다. 진행률·활동·라벨은 평가 근거일 뿐 점수로 자동 환산되지 않는다.
- **불확실:** 누가 과제와 라벨을 수정·삭제하거나 상태를 바꿀 수 있는지, 파일 제한, 피드백 수정·익명성, 완료 후 잠금 규칙은 없다.

## 3. 면담리뷰 기록 작성하기

[원문](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/%EB%A9%B4%EB%8B%B4%EB%A6%AC%EB%B7%B0-%EA%B8%B0%EB%A1%9D-%EC%9E%91%EC%84%B1%ED%95%98%EA%B8%B0/) · 업데이트 2025-12-18

- **기능/입력:** `인사 > 면담 관리 > 면담리뷰`에서 신규 작성을 열고 대상자를 검색한다. 선택적으로 참조자를 추가하고 면담·코칭 요약, 주요 이슈, 요청, 후속 조치를 자유 서술한다. 저장된 기록은 작성 목록에서 선택해 오른쪽 상세 영역으로 확인한다.
- **권한:** 작성자는 자신의 기록을 본다. 대상자와 참조자는 작성 시 해당 공개 옵션이 켜져야 열람할 수 있다. 조회 가이드의 표현을 함께 보면 대상자 공개와 참조자 공개는 별도 옵션일 가능성이 높다.
- **상태/단계:** 직원별로 기록을 누적해 이전 상담과 피드백 흐름을 이어가는 기능이다. 평가 점수나 등급에는 직접 반영되지 않는다.
- **관리자 의존:** 명시된 평가 관리자 설정은 없다. 다만 대상자·참조자 검색을 위한 직원 디렉터리와 메뉴 접근 권한은 전제된다.
- **불확실:** 임시저장, 수정·삭제, 첨부, 작성 완료 잠금, 알림, 관리자 열람·감사, 보존 기간은 설명하지 않는다.

## 4. 면담리뷰 조회하기

[원문](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/%EB%A9%B4%EB%8B%B4%EB%A6%AC%EB%B7%B0-%EC%A1%B0%ED%9A%8C%ED%95%98%EA%B8%B0/) · 업데이트 2025-12-18

- **기능:** 같은 메뉴에서 `내가 작성`, `나의 기록`, `직원별 기록`, `참조된 기록` 네 탭으로 역할별 조회 범위를 분리한다. 목록 선택 시 오른쪽에 상세를 표시한다.
- **권한:** `내가 작성`은 작성자 기준 전체, `나의 기록`은 자신이 대상자이면서 대상자 공개가 켜진 건, `직원별 기록`은 자신이 쓴 기록을 직원 검색으로 묶어 본다. `참조된 기록`은 자신이 참조자이면서 참조자 공개가 켜진 건만 보인다. 같은 기록도 사용자의 역할에 따라 다른 탭에 나타난다.
- **입력/상태:** 조회 입력은 탭 선택, 직원 검색, 기록 선택이다. 별도 업무 상태는 제시되지 않는다.
- **관리자 의존:** 열람 범위의 핵심은 관리자의 전역 공개 정책보다 작성자가 저장한 대상자·참조자 공개 플래그다.
- **불확실:** 한 사람이 여러 역할이면 중복 노출되는지, 비공개 전환이 기존 열람을 즉시 회수하는지, 관리자·감사자가 예외 열람하는지, 검색·정렬·페이지네이션 조건은 없다.

## 5. 평가 리포트 확인하기

[원문](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/%ED%8F%89%EA%B0%80-%EB%A6%AC%ED%8F%AC%ED%8A%B8-%ED%99%95%EC%9D%B8%ED%95%98%EA%B8%B0/) · 업데이트 2025-12-31

- **기능:** `평가 > 평가 리포트`는 최신 완료 평가의 점수·등급, 최근 5년 종합점수 추이 그래프, 최근 5년 점수 구간 분포, 전체 평가 이력을 한 화면에 집계한다. 이력에는 연도, 유형, 평가명, 점수, 등급이 포함된다.
- **권한/입력:** 구성원이 자신의 결과만 읽는 화면으로 설명되며 작성 입력은 없다. 다면·성과·역량 결과를 장기간 비교하는 자기 분석 용도다.
- **상태/관리자 의존:** 최신 값은 `완료된 평가`를 기준으로 한다. 실제 노출에는 관리자의 결과 계산·확정과 공개 정책이 선행될 것으로 보이나, 이는 평가 운영 흐름에 근거한 추론이며 이 페이지 자체는 공개 조건을 명시하지 않는다.
- **불확실:** 5년 범위의 기준일, 누락 연도 처리, 점수 정규화, 등급만 공개하는 정책 적용, 다운로드·상세 이동은 없다. 그래프와 이력 스크린샷 링크는 확인했지만 세부 축·컬럼은 안정적으로 판독하지 못했다.

## 6. 평가 결과 확인하기

[원문](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/%ED%8F%89%EA%B0%80-%EA%B2%B0%EA%B3%BC-%ED%99%95%EC%9D%B8%ED%95%98%EA%B8%B0/) · 업데이트 2025-12-31

- **기능:** `평가 > 평가 결과` 상단에 본인의 부서·직위와 최신 종합 점수·등급을 보여주고, 아래에 연도·유형·평가명·점수·등급으로 전체 이력을 나열한다. 의견은 별도 평가 피드백 메뉴에서 확인한다.
- **권한/입력:** 본인 결과 전용 읽기 화면이다. 페이지는 연도별·유형별 비교를 말하지만 명시적인 필터 입력이나 상세 진입 동작은 설명하지 않는다.
- **상태/관리자 의존:** 계산·확정되고 구성원에게 공개된 결과가 있어야 한다는 의존성이 예상된다. 공개 시점과 점수·등급별 공개 범위는 이 페이지에서 확인되지 않아 관리자 가이드로 검증해야 한다.
- **불확실:** `평가 리포트`와 데이터 원천은 같아 보이나, 리포트는 5년 시각화·분포에, 결과는 직원 정보와 목록에 초점을 둔다. 두 메뉴를 유지하는 이유, 미완료 평가 표시, 재계산·재공개 시 과거 스냅샷 처리, 결과 이의제기 흐름은 없다. 본문에는 별도 화면 이미지가 제시되지 않았다.

## 구성원 관점의 연결 흐름

```text
관리자가 부서 목표 설정
        ↓
구성원이 목표를 조회하고 성과과제를 연결
        ↓
과제 상태·진행률·활동·협업 피드백을 증빙으로 축적
        ↓
평가 계산·확정·공개 (관리자 가이드 확인 필요)
        ↓
평가 결과 목록과 5년 리포트 조회

면담리뷰 작성·역할별 공개·누적 ── 평가 점수와 직접 분리
```

## 관리자 가이드에서 우선 확인할 계약

1. 부서 목표의 생성 주체, 조직 범위, 기간·상태·가중치와 구성원 공개 조건
2. 성과과제에 연결 가능한 목표의 유효 상태와 관계자별 생성·수정·상태변경 권한
3. 평가 결과 계산 → 확정 → 공개의 상태 전이와 점수·등급·피드백별 공개 정책
4. 재계산·재공개 시 결과 이력과 5년 리포트가 사용하는 스냅샷 규칙
5. 면담리뷰의 관리자·감사자 예외 열람, 수정·삭제, 공개 철회, 알림과 보존 정책

## 용어·모델링 주의점

- 성과과제 종료 상태는 본문 `폐기`와 FAQ `휴지통`이 혼용된다. API enum과 화면 라벨을 정하기 전에 관리자 화면의 정식 용어를 확인해야 한다.
- `평가 리포트`와 `평가 결과`는 최신 점수·등급과 전체 이력이 겹친다. 공통 결과 스냅샷을 공유하고, 리포트는 집계 projection, 결과는 목록 projection으로 분리하는 해석이 현재 근거에 가장 잘 맞는다.
- 면담리뷰 공개는 기록 단위이며 대상자와 참조자 역할을 따로 판정해야 한다. 단순한 `public=true/false` 하나로 모델링하면 구성원 가이드의 조회 범위를 표현하기 어렵다.
