# RootHR evaluation reference flows (functional matrix)

Research date: 2026-09-07. These are implementation requirements inferred from public help pages. Reuse the interaction ideas and safeguards; do not copy RootHR copy, branding, images, or visual identity.

## End-to-end operating model

The reference lifecycle is **preparation → configure an evaluation → open → run ordered stages → calculate → calibrate → feedback/appeal → close and publish → report**. Stage visibility and transitions are conditional: an unfinished prior stage prevents the next stage from becoming available. [Overview](https://roothr.co.kr/guide/use-cases/evaulation/%EC%9D%B8%EC%82%AC%ED%8F%89%EA%B0%80-%EA%B4%80%EB%A6%AC-%EA%B0%9C%EC%9A%94/) · [Performance/competency runbook](https://roothr.co.kr/guide/use-cases/evaulation/%EC%84%B1%EA%B3%BC%C2%B7%EC%97%AD%EB%9F%89-%ED%8F%89%EA%B0%80-%EC%9A%B4%EC%98%81-%EA%B0%80%EC%9D%B4%EB%93%9C/)

| Close and publish | Closing changes the evaluation to final-complete and prevents result edits. Publication is separately controlled per subject; unpublished results remain internal. Expose per-person publish toggle and publication scope; lock writes after close and reflect published values in reports/statistics. ## Priority interaction slices for Easy Performance

1. **Cycle setup and stage gate:** conditional stage builder, preview, OPEN transition, and a dashboard that explains exactly why a person cannot advance.
2. **Review workspace:** subject list + progress counts, evidence context (goals/check-ins/interviews), draft save, complete/lock, and role-aware access.
3. **Result integrity:** deterministic calculation snapshot, calibration with target/current distribution, append-only adjustment history, close lock, and per-subject publication.
4. **Conversation loop:** formal feedback, employee acknowledgement or appeal, resolution, and immutable completion.
5. **Operational recovery:** safe explicit recalculation/close-cancel paths with audit events; no silent mutation of published outcomes.

## Paired admin ↔ member journeys

The public category roots are [Admin evaluation guides](https://roothr.co.kr/guide/admin-guide/evaulation/) and [Member evaluation guides](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/). Each admin operation should have a corresponding member state and action:
