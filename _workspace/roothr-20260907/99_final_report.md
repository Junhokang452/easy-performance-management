# 성과평가 정비·공통화 검증 보고서

관리자와 구성원 업무를 목표 합의부터 결과 확인·마감까지 연결했습니다. 화면은 easy-ware·easy-hcm의 공통 디자인 계열을 유지하고, 재사용할 UI와 기반 기능은 Easy Design System 및 easy-platform-core를 사용합니다.

## 구현 및 공통화

| 구분 | 반영 내용 |

| 평가자 | 배정된 직원의 목표 승인/반려, 중간점검 피드백, 항목별 평가 점수, 결과 면담 피드백 |

공통 자산은 중앙 저장소 로컬 커밋 `90439f4`에 등록했습니다. 성과관리에는 기존 백엔드 코어를 유지하면서 동일 자산만 반영한 `7c814bc`를 연결했습니다. 다른 자매품 코드를 바꾸거나 원격 저장소에 올리지는 않았습니다.

## Neon 운영 구조

**고객사 1곳 = Neon 프로젝트 1개 → 구매한 자매품별 DB**입니다. 성과관리 제품 코드는 `PERFORMANCE`, DB는 `performance`, 앱 역할은 `performance_app`입니다. 고객사의 테넌트 UUID는 자매품 간에 공유합니다.

공통 관리 DB는 고객·제품·암호화된 연결 정보를 관리하고, 평가 테이블은 고객사의 성과관리 DB에 적용합니다. 제품 DB 마이그레이션 경로와 기대 버전 `20260907.003`를 맞췄으며, 기존 ACTIVE 고객 DB 갱신은 명시적인 설정과 고객 UUID 목록으로 범위를 제한했습니다. 프로비저닝 준비가 없으면 고객 정보를 쓰기 전에 중단하고, 내부 관리자 경로에도 권한 검사를 적용했습니다.

**이번 실행은 독립 로컬 PostgreSQL 검증입니다. 실제 Neon 고객 프로젝트·제품 DB 생성, 공통 관리 DB 등록, 운영 마이그레이션은 실행하지 않았습니다.**

## 로컬 확인

- 화면: [로컬 성과평가](http://localhost:5174)
- 관리자: `dev-hr-admin@performance.dev`
- 평가자: `dev-manager@performance.dev`
- 구성원: `dev-employee@performance.dev`
- 합성 데이터 비밀번호: `dev`, 회사 코드는 비워 둡니다.
- 재시작: 저장소의 `scripts/local-demo.sh start`, 종료: `scripts/local-demo.sh stop`.

현재는 1차 평가자 한 명의 평가 흐름입니다. 여러 차수/360 평가, 이의 수용에 따른 등급 정정·버전별 재발행은 별도 확장 범위입니다. 미구현 등급 정정은 완료로 처리하지 않고 요청을 차단합니다. 실제 고객 운영에서는 HCM 사원 원장과 로그인 계정 연결도 준비되어야 합니다.

참고 자료: [RootHR 관리자 평가 가이드](https://roothr.co.kr/guide/admin-guide/evaulation/), [구성원 평가 가이드](https://roothr.co.kr/guide/member-guide/evaulation-member-guide/). 기능 대조는 `reference-flows.md`·`acceptance.md`, 공통 코어 검토는 `backend-core-reuse.md`, Neon 설정 검토는 `neon-topology-audit.md`, 실제 API 증거는 `api-flow-result.json`에 보존했습니다.
