# S1 HCM local sender contract

Scope accepted after the user's instruction to continue with Astra/Sol/Terra/Luna. Root owns new HCM sender, snapshot source, controller and focused tests. No existing sender, deployment, configuration value or scheduler is changed. Sol owns PA receiver/read-model/automation; Terra owns PA UI; Luna reviews both boundaries.

- New manual endpoint: `POST /api/admin/sync/easyperformance/push`, existing HCM `ADMIN` or `HR` authorities. No automatic schedule.
- Properties: `hcm.s2s.easyperformance.enabled` defaults false; `base-url`, `bearer-token`, `hmac-secret`, `tenant-id` default empty. Missing any setting means 503/no DB read/no HTTP. Secret uses existing HmacService validation. Base URL HTTPS, without credentials/query/fragment. The single operator-managed configured origin is the destination allowlist; no URL, host, path or tenant is accepted from the endpoint caller. Redirects are disabled. Infrastructure egress policy/DNS protection remains an activation prerequisite, not a claim of runtime DNS/IP pinning.
- Configured tenant UUID must equal authenticated HCM TenantContext and, when Model B is enabled, active TenantRoutingContext.Route.platformTenantId. Reject before snapshot on mismatch or missing route. No control DB fallback.
- Snapshot reads current routed HCM DB only in a separate read-only transaction. Explicit bounded SQL projection (max 10,000 rows per collection; overflow rejects the entire push), not ORM findAll. Native projection intentionally includes soft-deleted assignments and employees.
- Employee soft deletion maps to INACTIVE. Assignment adds managerEmployeeId and explicit Boolean deleted. sourceVersion = epoch **microseconds** of greatest(updated_at, deleted_at), retaining PostgreSQL timestamp precision (unlike existing other-target senders' millisecond truncation). The first microsecond value monotonically supersedes legacy millisecond values; this dedicated target has no former sender. Receiver treats the number as an opaque monotonic version, never a millisecond timestamp. Missing/nonpositive versions reject, not invent a current-time version. Effective dates are inclusive. Deleted rows remain tombstones.
- Payload preserves employees/orgUnits/assignments shapes and adds signed `tenantId`. `X-Tenant-Uuid` repeats the same UUID, and `X-Signature` authenticates the exact UTF-8 JSON body. PA validates signed tenantId against server tenant context before accepting automatic-line source capability.
- HTTP runs after snapshot transaction ends. Bounded connect/read timeout; no redirect following or automatic retry. No PII/raw body/secret logs. Failed HTTP does not claim success or advance a watermark (no watermark in this manual full snapshot).
- Unit/mock checks: disabled/missing settings no interactions; tenant/route mismatch denies before reads; active+deleted source shape; signed body/header; HTTP failure; transaction boundary; size limit. No live HCM/PA/Neon endpoints are called.

Existing manual/Excel reviewer assignment is preserved. Wire extensions are additive; legacy unsigned-tenant or missing-deleted relation data cannot qualify for automatic assignment. Operational activation remains a separate decision.

## Design review resolution (Root)

Phase3a design PASS; implementation verification pending. The single configuration-origin allowlist bounds SSRF without adding a user-controllable network input. Sol owns exact apply limits (1..100, duplicates rejected), idempotency via body previewHash scoped to tenant/program, and header/body/server tenant equality. A separate Idempotency-Key header is not required when the body key has persisted uniqueness and deterministic replay semantics. These are design decisions; runtime/boundary tests must verify them before S1 is reported complete.
